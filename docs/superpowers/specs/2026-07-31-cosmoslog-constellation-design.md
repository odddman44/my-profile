# cosmoslog 성좌 재설계

작성일: 2026-07-31
상태: 설계 승인 완료 · 문서 리뷰 대기
선행 문서: `2026-07-28-cosmoslog-profile-design.md` (이 문서가 화면 구조 부분을 대체한다)

## 1. 재설계하는 이유

배포된 사이트가 **평범한 개발자 포트폴리오로 읽힌다.** 원인은 배경이 아니라 구조다.

현재 정보 구조는 `히어로 → 나 → 만든 것들(카드 그리드) → 채널`인데, 이것은 포트폴리오 템플릿 그 자체다. 우주는 그 위에 깔린 벽지이고, 방문자가 할 수 있는 행동은 **스크롤 하나뿐**이다. 스크롤은 읽는 행위지 가지고 노는 행위가 아니다.

목표를 다시 정의한다.

1. **인터랙티브한 페이지인 것이 주된 속성이다.** 눌러보고 넘겨보는 재미가 사이트의 본질이다
2. 정체성(무엇을 하는 사람인지)이 담겨 있다
3. 만든 사이트들로 연결된다
4. 들어온 사람이 **"뭐 하는 페이지지?"** 하고 생각한다

1번이 최우선이다. 2·3번은 충족해야 할 요구사항이지 전면에 내세울 속성이 아니다.

### 설계 원칙

만질 수 있는 **개별 객체**가 화면에 **동시에** 존재해야 한다. 스크롤은 대상을 하나씩 지나가 버려서 만질 것을 남기지 않는다. 그래서 스크롤을 폐기한다.

## 2. 확정된 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 페이지 형태 | 성좌 — 스크롤 없는 단일 화면 | 만질 객체가 동시에 존재해야 함 |
| 항행 방식 | 궤도 회전 (좌우 드래그) | 자동으로 돌고 있어 안내 없이도 만지게 됨 |
| 첫 화면 | 중심에 나, 주변에 별 | 정체성 즉시 전달 + 탐험 유발 |
| 오프닝 | 워프 → 진입 → 감속 → 성좌 | 첫 인상에서 포트폴리오라는 인식을 깸 |
| 오프닝 재생 | **매 방문마다** | 사용자 결정 |
| 건너뛰기 | **워프 내내 상시 노출** | 강제 대기는 이탈로 이어짐 |
| 진입 버튼 문구 | `진입` | 사용자 결정 |
| 별의 구현 | **DOM 요소** (캔버스 아님) | 접근성·SEO·키보드 — 3절 참조 |
| 딥링크 | 없음 | 각 프로젝트가 자기 URL을 가짐, 패널은 미리보기 |

### 궤도 회전을 고른 이유

고정 배치·드래그 팬과 함께 실제 동작하는 시안 3종을 비교했다. 궤도 회전만이 **"3초 안에 이탈" 문제를 스스로 해결한다.** 나머지 둘은 정지 화면이라 방문자가 "드래그해보자"는 생각을 스스로 해야 하지만, 궤도는 이미 돌고 있어서 움직임 자체가 affordance가 된다. 안내 문구 없이 성립하는 유일한 안이다.

부수 효과로 확장에도 강하다. 프로젝트가 늘면 궤도를 균등 재분할하면 된다.

## 3. 별은 DOM 요소다 — 가장 중요한 구조 결정

시안에서는 별을 캔버스에 그리고 좌표 거리로 클릭을 판정했다. **실제 사이트에서는 그렇게 하지 않는다.**

캔버스 안의 그림은 접근성 트리에 존재하지 않는다. 스크린 리더가 읽지 못하고, 검색엔진이 인식하지 못하고, 키보드로 도달할 수 없다. 링크가 전부인 사이트에서 링크가 하나도 인식되지 않는 결과가 된다.

따라서 역할을 나눈다.

| 레이어 | 구현 | 역할 |
|---|---|---|
| 배경 | `<canvas>` (`aria-hidden`) | 성운, 잔별, 워프, 궤도선, 발광 |
| 별 | **DOM `<a>`** | 링크 그 자체. 매 프레임 `transform`으로 궤도 위치에 배치 |
| 패널 | **DOM** | 프로젝트 정보 |

이 구조에서 따라오는 것들:

- **Tab 키로 별 사이 이동**이 기본 동작으로 성립
- 스크린 리더가 링크 목록으로 읽음
- 검색엔진이 모든 링크를 인식
- 클릭 판정 코드가 불필요 (브라우저의 이벤트 처리를 그대로 씀)
- JS가 실패해도 링크는 HTML에 존재

**보이는 것은 우주지만 구조는 정상적인 링크 목록이다.** 요소가 10개 남짓이므로 매 프레임 `transform` 갱신에 따르는 성능 부담은 없다.

## 4. 시퀀스

```
[워프]   별이 관측자를 스쳐 지나감
         상단에 me.cosmoslog.org
         2.0초 후 [진입] 버튼 페이드인
         우측 하단에 작은 "건너뛰기" — 0초부터 상시
   ↓ 진입 또는 건너뛰기
[감속]   워프가 잦아들고 별들이 궤도로 빨려 들어옴
         항성 점화 · 약 1.6초 · 컷 없이 연속
   ↓
[성좌]   중심 항성 + 두 개의 궤도
```

**컷이 없다는 것이 핵심이다.** 화면이 전환되는 것이 아니라 날아가던 별이 감속해 그대로 자리잡는다. 같은 캔버스에서 이어지는 하나의 연출이다.

### 파라미터 (시작값)

| 항목 | 값 |
|---|---|
| 워프 별 개수 | 420 (모바일 200) |
| 워프 전진 속도 | z축 0.022/frame |
| 진입 버튼 등장 | **2.0초** |
| 감속 시간 | 1.6초 |
| 안쪽 궤도 반경 | `min(W, H*2.2) * 0.30` |
| 바깥 궤도 반경 | `min(W, H*2.2) * 0.43` |
| 궤도 타원 y 비율 | 0.34 |
| 자동 회전 | 0.0022 rad/frame |
| 깊이 스케일 | `0.62 + 0.38 * ((sin θ + 1) / 2)` |

## 5. 성좌 구조

| 위치 | 내용 |
|---|---|
| **중심 항성** | 오드 · 소프트웨어 엔지니어 — 이름과 역할은 항상 보임 |
| **안쪽 궤도** | 프로젝트 (현재 4개) |
| **바깥 궤도** | 채널 (GitHub, Email — 추후 인스타그램·블로그) |

중심 항성도 클릭 가능하다. 클릭하면 자기소개 문단이 열린다. 이름·역할은 즉시 보이므로 정체성이 확보되고, 더 깊은 소개는 탐험 대상이 된다. 다른 별과 상호작용 규칙이 같아져 일관성도 생긴다.

중심 항성 역시 **DOM 요소**다. 다만 외부로 나가는 링크가 없으므로 `<a>`가 아니라 `<button>`으로 만든다. 궤도를 돌지 않고 화면 중앙에 고정되며, 키보드 순서에서 **첫 번째**에 온다 — 방문자가 Tab을 처음 눌렀을 때 닿는 것이 "이 사람이 누구인가"여야 한다.

기존 "기록" 섹션은 별도로 두지 않는다. **블로그 주소가 데이터에 추가되면 채널 별이 하나 늘어나는** 방식으로 흡수된다.

### 확장

안쪽 궤도를 균등 분할한다. 10개까지는 한 궤도로 충분하고, 그 이상이면 궤도를 하나 더 추가한다. `projects.ts`에 객체를 추가하면 자리가 자동 재배치되므로 화면 코드는 수정하지 않는다.

## 6. 상호작용 규칙

### 회전

- 기본적으로 아주 느리게 자동 회전한다
- 좌우 드래그로 돌린다. 놓으면 관성으로 미끄러지다 기본 회전 속도로 수렴한다
- **패널이 열려 있는 동안 회전은 멈춘다.** 움직이는 글씨는 읽을 수 없다

### 정면 라벨

**정면에 온 별은 이름이 항상 표시된다.**

여기서 "정면"은 관측자에게 가장 가까운 위치, 즉 타원 궤도의 **아래쪽 끝**이다. 궤도 각도 θ에 대해 `sin θ`가 최대(=1, θ = π/2)인 지점이며, 이 지점의 별이 가장 크고 밝게 그려진다.

호버는 데스크톱에만 존재하므로 라벨을 호버에만 의존하면 모바일에서 아무 이름도 보이지 않는다. 정면 라벨은 이 문제를 해결하면서, 돌릴 때마다 이름이 차례로 바뀌어 **회전이 곧 넘겨보기**가 되게 만든다.

나머지 별은 호버 또는 키보드 포커스 시 라벨을 보여준다.

### 패널

- 내용: 이름 · 한 줄 설명 · 기술 태그 · `개발 중` 배지 · 바로가기 링크
- 한 번에 하나만 열린다
- 별을 클릭하면 그 별이 정면으로 이동하면서 열린다
- 데스크톱은 별 옆에 뜨는 카드, 모바일은 하단 시트
- 닫기: 빈 곳 클릭 · 닫기 버튼 · **Esc 키** 셋 다 지원

### 키보드

- Tab으로 별 사이를 이동한다. 포커스 시 라벨과 포커스 링이 보인다
- Enter로 패널을 연다
- **포커스 이동이 강제 회전을 유발하지 않는다.** Tab 할 때마다 화면이 도는 것은 방향 감각을 해친다
- Esc로 패널을 닫는다

## 7. 접근성

`prefers-reduced-motion: reduce`가 켜져 있으면:

- **워프 오프닝을 통째로 건너뛰고 성좌부터 시작한다.** 워프는 전정기관 장애가 있는 사용자에게 어지럼증을 유발하는 대표적 연출이다
- 자동 회전을 하지 않는다. 드래그로 직접 돌리는 것은 가능하다 (사용자가 의도한 움직임이므로)
- 배경 잔별의 표류·반짝임을 멈춘다

그 밖에:

- 캔버스는 `aria-hidden="true"`, `pointer-events: none`
- 터치 타깃은 시각적 크기와 무관하게 **44px 이상**을 보장한다 (투명 패딩)
- 본문 대비는 WCAG AA(4.5:1) 이상

## 8. 모바일

궤도 회전은 마우스를 전제한 연출이므로 그대로 옮기면 깨진다.

- **호버 없음** → 정면 라벨로 해결 (6절)
- **터치 타깃** 44px 이상 보장
- **패널**은 하단 시트로 전환
- **제스처**: Pointer Events로 마우스·터치를 한 경로에서 처리한다. 화면 가장자리 스와이프는 브라우저 뒤로가기(iOS Safari의 edge swipe)와 충돌하므로 **좌우 가장자리 24px을 회전 입력에서 제외한다**
- 워프 별 개수와 DPR 상한을 낮춘다

## 9. 파일 구조

```
src/components/cosmos/
  params.ts       유지 + 워프·궤도 파라미터 추가
  field.ts        유지 (배경 잔별)
  nebula.ts       유지
  warp.ts         신규 — 워프 별 전진·재생성·투영 (순수)
  orbit.ts        신규 — 궤도 좌표·깊이·정면 판정 (순수)
  renderer.ts     개편 — 배경/워프/궤도선만 그림
  engine.ts       개편 — 페이즈 상태머신 + 루프
  environment.ts  유지
src/components/stage/
  Stage.tsx       클라이언트 루트, 페이즈 관리
  StarLink.tsx    별 하나 = DOM <a>
  StarPanel.tsx   패널
  EnterButton.tsx 진입 / 건너뛰기
src/data/          그대로
src/types/         Phase 타입 추가
```

**`warp.ts`와 `orbit.ts`는 브라우저 API를 참조하지 않는다.** 지난 설계와 같은 원칙으로, 좌표 계산은 순수 함수로 분리해 DOM 없이 단위 테스트하고 캔버스와 React는 얇게 남긴다.

배경 잔별에 적용되던 **국지적 중력 렌즈는 유지한다.** 별이 DOM으로 분리되었으므로 회전 조작과 충돌하지 않는다.

## 10. 기존 코드 처리

| 그대로 살림 | 크게 고침 | 버림 |
|---|---|---|
| `field.ts` `nebula.ts` | `params.ts` (워프·궤도 파라미터 추가) | `Hero` `About` `Projects` `Writing` `Channels` |
| `environment.ts` | `renderer.ts` (별 그리기 제거, 워프 추가) | `ScrollProgress` `Reveal` `ProjectCard` `GlassPanel` |
| `data/*` `types/*` | `engine.ts` (페이즈 상태머신 도입) | 스크롤 기반 페이지 구조 전체와 그 테스트 파일 |

**이것은 수정이 아니라 재작성이다.** 데이터와 배경 엔진은 재활용되지만 화면 구조는 전부 새로 짠다.

`layout.tsx`의 메타데이터와 `globals.css`의 디자인 토큰은 대부분 그대로 쓴다.

## 11. 범위 밖

- **딥링크(URL 해시)** — 각 프로젝트가 자기 URL을 가지며 패널은 미리보기일 뿐이다
- **3D 라이브러리(Three.js 등)** — 2D 캔버스 + DOM으로 충분하고 번들만 무거워진다
- 검색·필터, 다국어, 관리 UI·DB
- 블로그 글 자동 수집

## 12. 완료 기준

1. 워프 → 진입 → 성좌가 컷 없이 이어진다
2. `prefers-reduced-motion`에서 워프를 건너뛰고 자동 회전이 없다
3. **Tab 키만으로** 모든 별에 도달하고 Enter로 패널이 열린다
4. JS 없이도 모든 링크가 HTML에 존재한다
5. 건너뛰기가 워프 내내 접근 가능하다
6. 모바일에서 스와이프로 회전하고 탭으로 열린다
7. `projects.ts`에 객체를 추가하면 궤도에 별이 하나 늘어난다
8. 정면에 온 별의 이름이 항상 보인다
9. 빈 링크(`href="#"`)가 하나도 없다
10. `npm test`와 `next build`가 통과한다

## 13. 미정 항목

데이터 파일만 고치면 되는 값들로, 이번 작업의 선행 조건은 아니다.

- 프로젝트 3개(blog·meetup·travel)의 실제 URL — 현재 모두 `https://vercel.com` 플레이스홀더
- 인스타그램 핸들, 블로그 주소
- 브랜드 컬러 (성운 blob 색상)
- 파비콘 — 현재 create-next-app 기본값
